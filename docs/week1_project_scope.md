# Week 1 — Project Scope

| Field | Details |
|-------|---------|
| **Project Name** | UniNet Recommender: Enhanced Hybrid Event Recommendation |
| **Domain** | Higher Education / Recommendation Systems (student event discovery) |
| **Problem Statement** | UniNet is a centralised event discovery platform that helps university students find technical opportunities such as programming competitions, workshops, talks and meetups. Its recommendation engine combines content-based filtering and item-to-item collaborative filtering, but its ranking weights are configured manually, matching relies on predefined tags, and user interests are not updated as they change over time. As a result, students may miss relevant opportunities and newly published events receive little exposure. AI engineering makes it possible to learn ranking from real interaction data and understand event descriptions semantically, while measuring whether recommendations actually improve. |
| **Evidence of the Problem** | **Evidence 1:** Event recommendation is a natural new-item cold-start problem. Events are short-lived and usually have little or no user feedback before they happen, so collaborative filtering alone cannot rank them well.<br>**Source / citation:** Macedo, A. Q., Marinho, L. B., & Santos, R. L. T. (2015). *Context-Aware Event Recommendation in Event-based Social Networks*. ACM RecSys, 123–130. https://doi.org/10.1145/2792838.2800187<br><br>**Evidence 2:** User preferences drift over time, and modelling these temporal dynamics significantly improved recommendation accuracy on the Netflix Prize dataset.<br>**Source / citation:** Koren, Y. (2009). *Collaborative Filtering with Temporal Dynamics*. ACM KDD, 447–456. https://doi.org/10.1145/1557019.1557072<br><br>**Evidence 3:** UniNet's current engine scores events with about ten hand-tuned weights, describes events using only 4 categories and 14 flairs, and keeps interest profiles that never decay.<br>**Source / citation:** UniNet source code, `uninet/netlify/shared/recommend.ts` |
| **Initial Related Work (at least 3)** | **Study / solution 1:** Amazon item-to-item collaborative filtering, which recommends items based on how often they are interacted with together. It is the basis of UniNet's current collaborative filtering.<br>**Source / citation:** Linden, G., Smith, B., & York, J. (2003). *Amazon.com Recommendations: Item-to-Item Collaborative Filtering*. IEEE Internet Computing, 7(1), 76–80. https://doi.org/10.1109/MIC.2003.1167344<br>**Key limitation:** It needs co-interaction history, so it cannot recommend new items that nobody has interacted with yet.<br><br>**Study / solution 2:** YouTube's deep neural network recommender, which splits recommendation into candidate generation and ranking, and trains the ranker on implicit feedback.<br>**Source / citation:** Covington, P., Adams, J., & Sargin, E. (2016). *Deep Neural Networks for YouTube Recommendations*. ACM RecSys, 191–198. https://doi.org/10.1145/2959100.2959190<br>**Key limitation:** It relies on massive datasets and large-scale infrastructure that a university-scale platform does not have.<br><br>**Study / solution 3:** Context-aware event recommendation, which combines content, social, location and time signals with learning-to-rank to recommend Meetup events.<br>**Source / citation:** Macedo, A. Q., Marinho, L. B., & Santos, R. L. T. (2015). ACM RecSys. https://doi.org/10.1145/2792838.2800187<br>**Key limitation:** It was evaluated only on English Meetup data, depends on social group signals, and does not handle multilingual content or recommendation diversity. |
| **Engineering Gap / Limitation** | **Gap / Limitation:** Existing approaches either fail on new items (item-to-item CF), need data and infrastructure far beyond a small platform (YouTube), or rely on English content and social signals (Meetup). UniNet's current engine has the same cold-start weakness and also uses hand-tuned weights, tag-only matching, static interest profiles, no negative feedback and no way to measure recommendation quality. What remains unresolved is a lightweight, data-driven and measurable ranking approach for a small, multilingual (Malay and English) university platform where events are short-lived. |
| **Initial Project Objectives (2–3)** | **O1:** To analyse UniNet's existing recommendation engine and current hybrid recommendation techniques, and identify their limitations.<br>**O2:** To design and develop an enhanced hybrid recommendation engine using multilingual sentence embeddings, time-decayed interest profiles, learned ranking models, a "Not Interested" feedback option and Maximal Marginal Relevance (MMR) re-ranking.<br>**O3:** To evaluate the enhanced engine against the existing one using offline metrics (Precision@K, NDCG@K, coverage and diversity) and, where feasible, online A/B testing of click-through and registration rates. |
| **Target Users** | University students in Malaysia who use UniNet to discover and register for technical events. Event organisers and university clubs benefit indirectly, because their newly published events get better exposure to relevant students. |
| **Data Sources (at least 2)** | **Source 1:** UniNet public event listings (titles, descriptions, categories, tags, deadlines) — URL: https://uninet.my<br>**Source 2:** Pre-trained multilingual embedding model card, paraphrase-multilingual-MiniLM-L12-v2 — URL: https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2<br>**Source 3:** Microsoft News Dataset (MIND), a public text-based recommendation benchmark with impression logs, used for supplementary offline evaluation — URL: https://msnews.github.io/<br>**Source 4 (private, not committed):** UniNet anonymised interaction logs (views, scroll depth, register clicks and completed registrations) |
| **Similar to EduAdvisor** | Both serve university students in the higher education domain. Both turn text documents into embeddings (EduAdvisor embeds PDF chunks, this project embeds event descriptions). Both are evaluated with objective, measurable criteria. |
| **Different from EduAdvisor** | This project is a recommendation and ranking system, not a generative question-answering assistant, so it outputs a ranked list of events instead of generated text and uses no large language model. It learns from implicit behavioural feedback (views, clicks, registrations) rather than answering explicit queries. It improves an existing, deployed system rather than building a new one, and it is evaluated with ranking metrics (Precision@K, NDCG@K) and A/B testing instead of groundedness and answer quality. |
| **Responsible AI Risks (at least 2)** | **Risk 1 — Filter bubble:** Learning only from past behaviour may keep showing students the same kind of event → students miss opportunities outside their usual interests. Mitigated with MMR diversity re-ranking.<br>**Risk 2 — Fairness and exposure bias:** Popular clubs and events in English may be ranked higher, while new, smaller or Malay-language events get less visibility → smaller organisers are disadvantaged and students see a narrower range of events. Measured through catalogue coverage and per-language exposure.<br>**Risk 3 — Privacy:** Interaction logs reveal what students browse and register for → misuse or leakage could expose personal behaviour. Mitigated by tag-level interest profiles instead of stored browsing history, anonymised training data, a personalisation opt-out and compliance with Malaysia's PDPA 2010.<br>**Risk 4 — Transparency:** Students cannot see why an event was recommended → lower trust, and biased rankings are harder to notice. |
