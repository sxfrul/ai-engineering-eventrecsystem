# Evaluation Criteria — UniNet Recommender: Enhanced Hybrid Event Recommendation
Version: 1.0

All offline criteria compare the **enhanced engine** with the **current UniNet engine (baseline)** on the same time-based hold-out set.

| Objective / Requirement ID | Evaluation Criterion | Capability Bucket | Measurement Method | Metric | Threshold | User / Business Outcome |
|----------------------------|----------------------|-------------------|--------------------|--------|-----------|-------------------------|
| O3 / NFR2 | Ranking relevance | Domain-specific capability | Offline replay. Rank each user's candidate pool as it stood before their hold-out interactions, then check where the events they went on to register for or engage with appear. | NDCG@10, Precision@10 | NDCG@10 ≥ 10% relative improvement over the baseline; Precision@10 not lower | Students find events they want near the top of the feed and scroll less. |
| O3 / FR2 / NFR3 | Cold-start exposure for new events | Domain-specific capability | The same offline replay, restricted to events less than 7 days old with no prior registrations. | Hit Rate@10 on new events | ≥ 15% relative improvement over the baseline | New events reach interested students before their deadlines, and organisers see more sign-ups. |
| O3 / FR3 | Adaptation to changing interests | Domain-specific capability | Offline replay for users with at least 4 weeks of activity, comparing profiles with and without time decay. | NDCG@10 on each user's latest week | Decayed profile ≥ non-decayed profile | Recommendations follow what students care about now, not what they clicked in their first semester. |
| O3 / RAI1 / RAI2 | Diversity and fair exposure | Domain-specific capability | Generate top-10 feeds for all active users offline, and count impressions per event, club and language. | Intra-list diversity; catalogue coverage; Malay-to-English exposure ratio | Diversity ≥ baseline; coverage ≥ 80%; ratio ≥ 0.8 | Students are not trapped in a filter bubble, and smaller clubs and Malay-language events still get seen. |
| O2 / FR4 / RAI4 | "Not Interested" is honoured | Instruction-following capability | Scripted test: reject 20 recommended events, then reload the feed and "More like this" over 7 simulated days. | Reappearance rate; change in average rank of similar events | 0% reappearance; similar events rank lower | Students feel in control of their feed, which builds trust in the recommendations. |
| O2 / FR7 / RAI3 | Personalisation opt-out is respected | Instruction-following capability | Audit the training dataset and the ranking inputs of test accounts that have personalisation turned off. | Opted-out users' records used in ranking or training | 0 | Students can trust the privacy setting, which keeps UniNet in line with PDPA 2010. |
| O3 / NFR1 | Ranking latency | Cost and latency | Time the on-device ranking step over 100 feed loads on a mid-range phone and a laptop. | p90 ranking time | < 100 ms | The feed feels instant, even on lower-end phones. |
| O3 / NFR4 | Operating cost | Cost and latency | Compare cloud usage dashboards (Firestore reads, function run time, Redis commands) over a 7-day run with the baseline. | Additional monthly cost; Firestore reads per feed open | RM 0; ≤ baseline + 1 | UniNet stays free to run, so the improvement is sustainable for a student-built platform. |
| O3 / NFR2 | Online engagement (where feasible) | Domain-specific capability | A/B test: split users 50/50 between the baseline and the enhanced engine for at least 2 weeks. | Feed click-through rate; registration conversion rate | Both ≥ baseline (no worse); an improvement is the goal | Confirms that offline gains turn into real registrations, which is UniNet's core goal. |

**Note on capability buckets:** the *Generation capability* bucket is not used. The system produces ranked lists of existing events, not generated text, so there is no generated output to judge for clarity or fluency.

**Reflection — which criterion matters most for usefulness?**
Ranking relevance (NDCG@10, O3 / NFR2) matters most. Students only look at the first few events in a feed, so the question that decides usefulness is whether the events they would actually register for appear near the top. The other criteria protect that goal (cold start, diversity, latency, privacy), but none of them matters if the top of the feed is not relevant. Because offline replay is biased towards the old ranking, the online A/B test of registration rate is the strongest final confirmation, where it can be run.
